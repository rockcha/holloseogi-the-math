# 홀로서기

## 논술 일정 설정

기존 `students` 테이블과 `classes.sql`의 교사 권한 함수가 있는 프로젝트에서 `supabase/essays.sql` 전체를 Supabase SQL Editor로 실행하세요.

- 왼쪽 `결제` 다음의 `논술` 메뉴에서 `일정 보기`, `대학 리스트`, `학교 추가`를 순서대로 사용할 수 있습니다. 학교 추가는 모달로 열립니다.
- `essays`의 한 행은 하나의 시험입니다. 같은 대학도 유형·계열·시험 구분명·날짜·시간에 따라 별도 등록하며, 목록·달력·수정·삭제·학생 배정은 각 시험 ID를 기준으로 처리합니다. 동일한 시험의 중복 저장은 DB에서 막고 화면에 안내합니다.
- 학교 추가·수정에서 시험 시간과 특징 메모를 입력하며, 시험 구분명 입력란은 표시하지 않습니다. 기존 시험 구분명은 유지하고, 값이 없으면 저장 시 선택한 계열명으로 자동 설정합니다. 모집단위·출제 형식·출제 과목·수능최저 입력란은 표시하지 않으며, 신규 등록 시 빈 값으로 저장하고 수정 시 기존 값을 유지합니다. 시험 시간은 `09:00`, `오전` 등의 텍스트이며 미확정이면 비워 둡니다.
- 달력·대학 리스트에 시험 구분명과 시간을 표시하고, 상세 화면은 대학명, 시험 구분명, 날짜·시간, D-day, 특징 메모, 학생 목록으로 구성합니다. 상단 돌아가기 링크와 유형·계열 정보, 모집단위·출제 형식·과목·수능최저는 표시하지 않습니다. 대학 리스트 검색은 시험명·모집단위·출제 형식·과목·수능최저도 포함합니다.
- `essay_students`는 기존 학생과 논술 일정의 다대다 연결 테이블입니다. 학생을 계속 추가·제외할 수 있으며, 일정을 삭제하면 배정만 함께 삭제됩니다.
- 약술은 인문·자연, 인문 논술은 인문·사회·자연 계열을 지원합니다. UI와 DB 양쪽에서 제한합니다.
- 일정 보기와 대학 리스트 모두 유형과 계열을 별도로 필터링합니다. 약술 선택 시 사회 계열 필터는 해제되며, 검색창은 한글 조합이 완료된 뒤 검색어를 URL에 반영합니다.
- 논술 일정은 모든 승인된 교사가 함께 조회·수정·삭제합니다. `teacher_id` 컬럼을 사용하지 않습니다. 학생 선택은 기존 학생 조회 권한을 따르며, 미선택 시 빈 배열로 저장합니다. `save_essay` 함수가 일정과 배정을 한 트랜잭션으로 저장합니다.
- `일정 보기`(`/essays`)는 달력과 유형 필터를 제공합니다. `대학 리스트`(`/essays/list`)는 모든 날짜의 대학 일정을 목록으로 보여주며 학교·계열·특징 검색과 유형 필터를 제공합니다. D-day는 브라우저의 오늘 날짜를 기준으로 계산합니다.
- 학교 클릭 시 상세 페이지에서 수정·삭제 및 학생 배정을 관리합니다.
- 검증: `node src/lib/essays.test.js`, `npm run lint`, `npm run build`.

React, TanStack Query, Supabase로 구성한 Vite 프로젝트입니다.

## 시작하기

```bash
npm install
copy .env.example .env
npm run dev
```

`.env`에서 Supabase URL과 공개 키를 실제 프로젝트 값으로 바꿔 주세요.

## 선생님별 시간표·수업 리스트

`supabase/teacher-timetable.sql`을 Supabase SQL Editor에서 실행하세요. 선생님 선택 메뉴에 필요한 교사 이름 목록과 다른 교사의 수업 시간표를 조회하는 함수를 추가합니다.

- 시간표와 수업 리스트에서 기본 선택은 본인입니다. 다른 선생님을 선택하면 해당 선생님의 수업만 표시합니다.
- 다른 선생님의 수업은 이름·요일·시작/종료 시간만 확인하는 모달로 열립니다. 이 화면에서는 추가·수정할 수 없고 개인 반복 일정은 표시하지 않습니다.
- 기존 학생·출석·결제 화면의 조회 정책은 변경하지 않습니다.

## 일정 관리 설정

기존 `classes.sql`을 적용한 Supabase 프로젝트의 SQL Editor에서 `supabase/schedules.sql`을 실행하세요. `schedules` 테이블과 교사 권한 정책을 생성합니다. 공개 클라이언트 키만으로는 테이블을 생성할 수 없습니다.

- 시간표의 `일정 추가`에서 제목, 반복 요일, 시작/종료 시간, 색상, 메모를 입력합니다. 일정은 매주 선택한 요일에 표시됩니다.
- `담당 수업`에서는 본인이 작성한 일정, `전체`에서는 교사들의 일정을 함께 표시합니다. 수정·삭제는 작성자만 가능합니다.
- 시간표의 일정 박스를 클릭하면 메모 확인과 수정·삭제가 가능합니다. 수업과 겹치는 일정은 나란히 표시됩니다.
- 일정은 수업·출석·납부 회차에 영향을 주지 않습니다. 입력은 같은 날의 시작/종료 시간이며 자정을 넘기는 일정은 나누어 등록합니다.
- 검증: `node src/lib/schedule.test.js`.

## 월간 달력 설정

Supabase SQL Editor에서 `supabase/calendar-events.sql`을 실행하면 왼쪽 메뉴의 `일정`(`/calendar`)에서 월간 달력의 날짜별 일정을 저장할 수 있습니다. 기존 `classes.sql`의 교사 권한 함수를 사용하며 기존 반복 일정 테이블은 변경하지 않습니다.

- 달력에는 본인 수업을 등록된 요일마다 초록색으로 표시합니다. 상단 시간표의 전체 보기 필터와 별도로 본인 수업만 표시합니다.
- 새 일정은 날짜와 제목만 입력하면 시간제한 없이 저장합니다. `시간제한 없음`을 해제하면 시작/종료 시간을 지정할 수 있습니다. 유형과 색상 선택은 없으며 추가 일정은 보라색으로 표시합니다.
- 날짜 또는 `+n개 더 보기`를 누르면 해당 날짜의 전체 목록 모달이 열립니다. 달력 아래에는 별도 목록을 표시하지 않습니다. 일정별 메모는 최대 5,000자로 입력하며 목록 모달과 편집 화면에서 확인합니다.
- 기존 `calendar_events` 테이블에는 `supabase/calendar-event-memos.sql`을 실행해 메모 컬럼을 추가하세요. 신규 설치용 `calendar-events.sql`에도 포함되어 있습니다.
- 이전/다음 달, 오늘 이동, 일정 수정·삭제를 지원합니다. 기존 수업은 현재 등록된 반복 요일을 기준으로 표시하며 과거의 수강 이력이나 휴강을 복원하지 않습니다.
- 검증: `node src/lib/calendar.test.js`.

## 오전 8시 알림 설정

`classes.sql`, `schedules.sql`, `calendar-events.sql` 적용 후 Supabase SQL Editor에서 `supabase/daily-notifications.sql` 전체를 실행하세요. 본인 알림 테이블과 조회 함수를 만들며, 읽음 상태는 DB에 저장됩니다.

- 닉네임 왼쪽 벨에 오늘의 수업·일정 요약과 미확인 빨간 점을 표시합니다. 알림을 열면 읽음 처리합니다.
- 기준 시간은 서버의 `Asia/Seoul`입니다. 오전 8시 이후 앱이 조회할 때 하루 한 건을 만들며, 켜진 앱에서는 1분 간격과 창 복귀 시 확인합니다. 8시 이후 처음 접속해도 표시됩니다.
- 수업은 본인 수업 중 오늘 요일에 해당하는 건수, 일정은 본인의 오늘 반복 일정과 오늘 날짜의 달력 일정 합계입니다. 데이터가 바뀌면 다음 조회에서 숫자를 갱신하고 읽음 상태는 유지합니다.
- 사이트 안의 알림입니다. 브라우저가 닫힌 동안 예약 실행하거나 휴대폰으로 푸시하지 않습니다. 비로그인·비교사 계정에는 생성되지 않습니다.

## 결제 관리 설정

기존 수업/학생 테이블과 정책을 적용한 Supabase 프로젝트에서 `supabase/payments.sql` 전체를 SQL Editor로 실행하세요. 기존 수업은 수업 상세에서 결제 시작일과 금액을 설정해야 주기별 조회가 가능합니다. 새 수업은 주기(회), 금액(원), 시작일을 입력합니다.

- 시작일을 1회차로, 등록된 수업 요일마다 회차를 계산합니다. 결석과 출석부 작성 여부는 회차를 바꾸지 않습니다. 예: 월·수 수업, 2026-09-07 시작, 8회 주기 → 첫 주기는 09-07~09-30, 두 번째는 10-05~10-28입니다.
- `/payments`의 수업별 결제 관리에서 이번 단위기간의 수업별 납부 현황을 확인합니다. 전원 완납이면 ‘납부 완료’, 일부 납부 또는 미납 학생이 있으면 ‘미납 학생 N명’을 결제 내역으로 자동 계산합니다. 학생이 없는 수업과 결제 설정이 없는 수업은 별도로 표시합니다.
- 수업을 선택하면 `/payments/classes/:classId`로 이동해 학생별 완납/일부 납부/미납을 확인합니다. 이전/다음 단위기간과 주기 번호로 기간을 변경하며 `?cycle=번호`에 선택을 보존합니다. 현재 참여 학생 및 해당 주기 결제자가 표시되며 과거 수강 명단을 별도로 복원하지 않습니다.
- `/payments/history`는 모든 수업 및 일반 결제 내역을 최신 결제일 순으로 모아 보여줍니다. 학생 이름 검색과 수업 필터를 지원합니다. 이 화면 분리를 위한 추가 SQL 적용은 필요하지 않습니다.
- 결제 내역 추가에서 학생·실제 금액·결제일을 입력합니다. 수업과 주기를 연결하면 해당 주기 납부액에 합산됩니다. 수업을 연결하지 않은 일반 결제는 전체 내역에만 표시됩니다. 결제일과 주기는 독립적이므로 선납과 후납도 기록할 수 있습니다.
- 결제 리스트의 `수정` 버튼에서 본인이 등록한 내역의 학생·수업·단위기간·금액·결제일을 수정합니다. 저장하면 리스트와 납부 현황을 갱신합니다. 금액·날짜만 수정하면 수강 종료 학생이나 과거 단위기간의 내역도 기존 주기와 기준 금액을 보존합니다.
- 수정 기능을 사용하려면 기존 결제 SQL 적용 후 `supabase/payment-edit.sql` 전체를 SQL Editor에서 실행하세요. 신규 설치도 마지막에 실행해야 합니다. 본인 결제의 입력 필드에만 수정 권한을 부여하며, 학생·수업·주기를 변경하면 DB에서 수강 여부를 검증하고 단위기간을 다시 계산합니다.
- 결제 리스트의 관리 열에서 본인이 등록한 결제를 `삭제`할 수 있습니다. 확인창에서 학생·수업·금액·결제일을 확인한 후 삭제하며, 성공하면 목록과 납부 현황을 갱신합니다. 삭제한 내역은 복구할 수 없습니다.
- 삭제 기능을 사용하려면 기존 결제 SQL 적용 후 `supabase/payment-delete.sql` 전체를 SQL Editor에서 실행하세요. 신규 설치도 마지막에 실행해야 합니다. 승인된 교사가 본인의 결제만 삭제하도록 DB 권한을 제한합니다.
- 결제가 기록된 수업은 요일·결제 주기·시작일·기준 금액 변경 및 삭제를 DB에서 막아 기존 내역을 보존합니다. 새 조건은 새 수업으로 등록하세요.

검증: `node src/lib/payments.test.js`, `npm run lint`, `npm run build`.

결제 시작일 없이도 수강 수업을 선택해 결제를 추가할 수 있습니다. 기존 DB에는 `supabase/payments-without-start-date.sql`을 실행하세요 (신규 설치는 수정된 `payments.sql`에 포함). 수업 연결을 유지한 채 ‘주기 미지정’으로 저장하며 전체 결제 내역에서 조회합니다. 이후 시작일을 설정해도 기존 미지정 내역을 특정 주기에 자동 배정하지 않습니다. 주기 미지정 결제만 있는 수업은 결제 설정을 변경할 수 있습니다.
